Java Web Dünyasının Kalbi: Servlet Mimarisi ve Spring MVC'nin Çalışma Mekanizması

Modern Java ekosisteminde Spring Boot ile çalışırken yalnızca birkaç anotasyon (@RestController, @GetMapping) ekleyerek saniyeler içinde REST API uçları yayınlayabiliyoruz. Ancak bu sihirli pratikliğin arkasında, 25 yılı aşkın süredir Java web dünyasının omurgasını oluşturan köklü bir standart yatar: Java Servlet Spesifikasyonu.

"Spring Boot'un konfigürasyon büyüsünü gerçekten anlamak ve yüksek yük altında doğru kararlar verebilmek, alttaki Servlet konteynerinin (Tomcat) HTTP isteklerini nasıl karşıladığını bilmekten geçer."

1. Web Konteyneri (Servlet Container) Nedir?

Geleneksel bir web sunucusu (Nginx, Apache HTTPD) yalnızca statik dosyaları (HTML, resim, CSS) sunarken; Java kodunu dinamik olarak çalıştıracak bir çalışma ortamına ihtiyaç duyarız. İşte bu ortama Servlet Konteyneri (Web Container) denir (Örn: Apache Tomcat, Eclipse Jetty, Undertow).

Konteynerin üstlendiği temel görevler:

  • Ağ & Soket Yönetimi: TCP/IP bağlantılarını kabul eder, HTTP istek metnini parse ederek Java nesnelerine (HttpServletRequest) dönüştürür.
  • Thread Havuzu (Thread Pool): Her gelen HTTP isteğini işletim sisteminden yeni bir thread açmak yerine önceden hazırlanmış bir thread havuzundan (Worker Thread) bir iş parçacığına teslim eder.
  • Yaşam Döngüsü (Lifecycle) İdaresi: Servlet sınıflarının belleğe yüklenmesini, başlatılmasını ve sonlandırılmasını yönetir.

2. Servlet Yaşam Döngüsü (Lifecycle)

Bir Servlet sınıfı, konteyner tarafından yönetilen 3 ana evreden geçer:

  1. init(ServletConfig config): Servlet belleğe yüklendiğinde yalnızca bir kez çalıştırılır. Ağır konfigürasyonlar ve kaynak bağlantıları burada kurulur.
  2. service(HttpServletRequest req, HttpServletResponse res): Gelen her istek için eşzamanlı olarak farklı bir thread içerisinde tetiklenir. HTTP metoduna göre (GET, POST, PUT, DELETE) ilgili doGet() veya doPost() metodunu çağırır.
  3. destroy(): Uygulama kapatılırken veya konteyner durdurulurken açık kalan dosya ve veritabanı bağlantılarını temizlemek için bir kez çağrılır.
Kritik Multithreading Uyarısı:

Servlet nesneleri bellekte Singleton olarak yaşar; ancak service() metodu aynı anda yüzlerce thread tarafından çağrılabilir. Bu yüzden bir Servlet (ve dolayısıyla Spring Controller) içinde kesinlikle durum tutan (stateful) sınıf değişkeni (instance variable) tanımlanmamalıdır; aksi halde thread-safety ihlali ve veri karışması yaşanır!

3. Spring MVC'nin Gizli Kahramanı: DispatcherServlet

Geleneksel Jakarta EE dünyasında her URL için ayrı bir Servlet yazmak gerekirdi (/users için UserServlet, /orders için OrderServlet). Bu durum devasa bir kod tekrarına yol açıyordu.

Spring Web MVC, bu sorunu Front Controller Tasarım Şablonu ile çözdü. Spring Boot uygulamanıza gelen tüm HTTP istekleri öncelikle tek bir merkezi servlete yönlendirilir: DispatcherServlet.

DispatcherServlet isteği aldığında şu adımları izler:

  • HandlerMapping: İsteğin URL'ine ve HTTP metoduna bakan bileşen, bu isteği hangi @Controller sınıfının hangi metodunun karşılayacağını bulur.
  • HandlerAdapter: İlgili controller metodunu çalıştırır; JSON body'sini Jackson kütüphanesiyle DTO nesnesine deserialize eder.
  • HttpMessageConverter: Metodun döndüğü nesneyi (örneğin DTO) tekrar JSON formatına serialize ederek HTTP Response Body'sine yazar.

4. Filter vs. Interceptor: Farkı Bilmek Neden Önemli?

İstekleri Controller'a ulaşmadan önce araya girip incelemek veya değiştirmek istediğimizde iki mekanizma karşımıza çıkar:

  • Servlet Filter: Konteyner seviyesindedir. İstek henüz Spring context'ine ve DispatcherServlet'e girmeden önce çalışır. Karakter kodlaması (UTF-8), CORS yapılandırması ve düşük seviyeli istek loglaması için idealdir.
  • HandlerInterceptor: Spring MVC seviyesindedir. DispatcherServlet'ten sonra, Controller metodundan önce ve sonra çalışır. Spring bean'lerine doğrudan erişebilir; kullanıcı yetki doğrulaması ve iş akışı metrikleri için tercih edilir.

Sonuç: Temelleri Bilmenin Gücü

Java'da Servlet mimarisini ve Tomcat'in thread havuzunu anlamak; bir gün prodüksiyon ortamında "Connection Timeout", "Too Many Open Files" veya bellek kilitlenmeleriyle karşılaştığınızda sorunu dakikalar içinde tespit edip çözmenizi sağlayan en büyük mühendislik avantajıdır.
